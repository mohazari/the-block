# Decision log

A running record of the choices made while building The Block and why. Newest sections are
appended per slice; each slice ships as its own reviewed PR.

## How this was built

- **Workflow:** the work is split into slices (setup → domain → API → realtime → UI → polish).
  Each slice is built, code-reviewed, tested, committed on a branch, and merged via PR once CI is
  green. The PR history is the audit trail.
- **AI usage:** built with Claude Code as a pair. I set the product direction, the constraints, and
  the review bar; the agent did repo/data analysis, drafted code, and ran reviews. Every slice was
  reviewed before merge. Two design references were consulted:
  - [ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) — its search
    tool classified the product as an _Auction Platform_ (bid-green / outbid-red / countdown-amber
    semantics, live-region accessibility rules). Used critically: its suggested _Playfair Display_
    body font and _dark-first_ theme were rejected (see Design below).
  - [Motion](https://github.com/motiondivision/motion) — animation library (`motion/react`).

## Slice 0 — Repo setup

| Decision                                                   | Why                                                                                                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Monorepo: `server/` (FastAPI) + `web/` (Vite)**          | Both halves in one PR stream; one `npm run dev` starts everything.                                                                                                   |
| **Python + FastAPI + SQLite**                              | Pydantic validates every bid at the edge; FastAPI gives reviewers interactive docs at `/docs`; SQLite needs zero setup yet supports real transactions for bid races. |
| **uv for Python**                                          | One command installs the right Python _and_ the locked deps — reviewers don't need a pre-configured Python.                                                          |
| **npm workspaces**                                         | A single root `npm install` installs the web app; root scripts orchestrate both stacks.                                                                              |
| **Vite proxy `/api` → `:8000`**                            | Same-origin in dev: no CORS configuration, and `EventSource` (SSE) works unchanged.                                                                                  |
| **TypeScript 7 + oxlint** (current Vite template defaults) | Native-speed typecheck and lint; kept rather than swapping in older tooling. `strict` + `noUncheckedIndexedAccess` on.                                               |
| **ruff + mypy (strict) + pytest with warnings-as-errors**  | Fast lint/format, real type safety, and deprecations surface immediately (e.g. Starlette's `httpx` → `httpx2` switch was caught this way).                           |
| **CI on every PR** (GitHub Actions)                        | "Tested" is visible on GitHub, not just claimed. Actions pinned to verified release tags.                                                                            |
| **Dependency freshness policy**                            | Pin fast-moving libraries to a release ≥ ~2 weeks old (e.g. Motion `14.2.0`, not the day-old `14.7.1`) — brand-new releases have had little real-world exposure.     |
| **Original brief kept at `docs/CHALLENGE.md`**             | The root README becomes the submission README, as the brief asks.                                                                                                    |

## Slice 1 — Auction domain & data

| Decision                                                                                                                                                | Why                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Pure rule module** (`server/app/domain/`) with `now` passed in                                                                                        | Every auction rule is deterministic and unit-tested without a DB or sleeping; the API, the bid transaction and the simulator share one implementation.                                                                           |
| **Clock normalization:** keep the dataset's relative schedule, shift it so the first auction closes 20 min after seeding; **4-day timed auctions**      | Literal dates are all in the past. Simulated 48/72/96/120h durations against the data: 96h gives 112 live / 88 upcoming, and a countdown hits zero early in any demo.                                                            |
| **Pre-bids on upcoming auctions**                                                                                                                       | 43 vehicles that land in "upcoming" already carry bids in the dataset. Rather than discard data, model what wholesale lanes do: proxy bids before the car runs.                                                                  |
| **Status is derived, never stored**                                                                                                                     | `upcoming/live/ended` come from `starts_at`/`ends_at` vs. the clock — cannot go stale, no cron job to flip states.                                                                                                               |
| **Increment ladder** $100 → $250 → $500 → $1,000 at $5k / $15k / $50k                                                                                   | Meaningful steps on a $3k sedan and a $60k truck alike.                                                                                                                                                                          |
| **Reserve amount is server-only**                                                                                                                       | Buyers see _met / not met / no reserve_, as on real platforms; the number never leaves the API.                                                                                                                                  |
| **Soft close (2 min)**                                                                                                                                  | A late bid re-arms the window so rivals can respond; sniping stops paying.                                                                                                                                                       |
| **Bid guards:** no raising your own winning bid; max single jump = 3× the minimum; a bid at/above an available Buy Now price is refused (`use_buy_now`) | The first only costs the buyer money; the second catches an extra-zero typo; the third would only lead the auction when the buyer could simply own the car.                                                                      |
| **Damage severity** (cosmetic / mechanical / major) by whole-word keyword, most severe first                                                            | Buyers price a scratch, budget a transmission, and walk away from frame/flood/airbag/water intrusion. Verified against all 30 distinct notes in the data.                                                                        |
| **Synthesized bid history** that obeys the increment ladder (fixed RNG seed); stored `bid_count` = actual bid rows                                      | The data has `bid_count` but no bids. 34 vehicles claim more bids than _any_ increment rule allows (e.g. 11 bids within $500), so those histories keep as many valid bids as fit — the bids table is the single source of truth. |
| **Concurrency: `BEGIN IMMEDIATE` for write sessions**                                                                                                   | The bid path reads the price then writes; taking SQLite's write lock up front prevents two bidders both "winning" at the same price. Proven by a two-thread test. (Postgres: `SELECT … FOR UPDATE`.)                             |
| **Integers for money, UTC-aware datetimes everywhere**                                                                                                  | No float rounding on prices; a custom column type rejects naive datetimes.                                                                                                                                                       |
| **Auto-reseed** when the DB is empty, from an older schema version, or every auction has closed — atomically, in one `BEGIN IMMEDIATE` transaction      | A reviewer cloning next week still gets a live marketplace; concurrent startups can't double-seed; a failed seed leaves the old data. `npm run reset-db` forces it.                                                              |
| **Bidder aliases** (`Bidder 4821`, 9,000 buckets) — collisions accepted                                                                                 | Purely cosmetic: "You" is decided by bidder id, never by alias.                                                                                                                                                                  |
| **SQLite only** (non-SQLite `DATABASE_URL` rejected at startup)                                                                                         | The engine setup is SQLite-specific by design; failing loudly beats a confusing driver error.                                                                                                                                    |

## Slice 2 — Inventory API

| Decision                                                                                                                        | Why                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`GET /api/vehicles` with a validated query model** (`extra="forbid"`)                                                         | All filters, bounds and sorts are validated in one Pydantic model; a typo like `?colour=red` is a 422 naming the field, not a silently ignored filter.                             |
| **Keyword search: every token must match** a precomputed lower-cased `search_text` (make, model, trim, VIN, lot, dealer, city…) | "2021 ford calgary" narrows as a buyer expects; VIN and lot lookups work from the same box. `LIKE` wildcards are escaped. Fine for 200 rows; FTS5 would be the next step at scale. |
| **Disjunctive facet counts**                                                                                                    | Each facet's counts ignore its own selection, so with _Ford_ selected the buyer still sees "BMW (14)" — the count they'd get by adding it.                                         |
| **Default view = open auctions; "ending soon" ranks live (by close) → upcoming (by open) → ended (most recent first)**          | That's the decision a buyer is making right now. Ranking by status first stays correct even when soft close pushes a live auction's end past an upcoming one's.                    |
| **Price filters/sorts use the current price** (`current_bid` else `starting_bid`)                                               | What a buyer would actually pay next, not a stale starting bid.                                                                                                                    |
| **Stable pagination** (`lot` tiebreak on every sort)                                                                            | No duplicates or gaps when paging.                                                                                                                                                 |
| **One error envelope** `{"error": {code, message, …}}` — including framework 404/405 and unexpected 500s                        | The client branches on stable codes everywhere and can render field-level issues; nothing falls back to FastAPI's `{"detail"}` shape.                                              |
| **`server_time` in responses**                                                                                                  | Countdowns are computed against server time, so a skewed laptop clock can't show the wrong time left.                                                                              |
| **Anonymous `X-Bidder-Id` header**, validated; rival ids refused                                                                | Enough identity for "You're winning" and My Bids without accounts; clients can't impersonate the simulated rivals.                                                                 |
| **Response models are the privacy boundary**                                                                                    | `reserve_price` and raw bidder ids have no field in any schema, so they cannot leak; a test asserts it.                                                                            |
| **Selected facet values are always returned** (count 0 if needed)                                                               | A buyer can always see and clear an active filter, even when other filters zero it out.                                                                                            |
| **Inverted ranges are a 422**                                                                                                   | Swapped slider handles are a client bug worth surfacing, not an empty result.                                                                                                      |

## Slice 3 — Bidding API

| Decision                                                                                                                                  | Why                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`POST /api/vehicles/{id}/bids` is one `BEGIN IMMEDIATE` transaction** (idempotency lookup → read price → validate → write → soft close) | No other bidder can interleave between reading the price and writing the bid. A 6-thread test fires identical bids at once: exactly one wins, five get `bid_too_low`.                                              |
| **Rejections are `409` with a stable code, a human message and a fresh auction snapshot**                                                 | The UI can recover in place — "You were outbid while confirming; the minimum is now $23,800" — without another round trip.                                                                                         |
| **`Idempotency-Key` header** (unique per bidder)                                                                                          | A retried request after a network blip returns the original bid (`200`) instead of bidding twice; reusing a key for a different bid is a `409`.                                                                    |
| **Buy Now closes the auction immediately as sold**; available on upcoming lots too                                                        | Buying an upcoming car also pulls `starts_at` back to now — otherwise derived status would still say "upcoming" after the sale (caught in design, covered by a test).                                              |
| **Pre-bids never trigger soft close**                                                                                                     | Only live bids near the close should extend it.                                                                                                                                                                    |
| **`GET /api/me/bids`** with a derived standing: leading / outbid / won / lost                                                             | The buyer's second most important screen: what am I winning, what do I need to act on. Open auctions first, closing soonest.                                                                                       |
| **Watchlist via idempotent `PUT`/`DELETE /api/me/watchlist/{id}`**                                                                        | Safe to retry; toggling from the UI never errors on double clicks.                                                                                                                                                 |
| **Concurrency test at the service layer with real threads**                                                                               | `TestClient` serializes requests on one event loop, so it can't prove anything about races.                                                                                                                        |
| **Read the clock only after taking the write lock** (`now` is judged inside the transaction)                                              | A bid that queued behind other writers for 3s must be judged — live or ended, soft close or not — and timestamped when it actually runs. Found in review; a test asserts the clock is read inside the transaction. |
| **Idempotent replays must match vehicle, kind (bid / buy now) and amount**                                                                | Otherwise a key first used for a $12,000 bid could "replay" as a successful Buy Now.                                                                                                                               |
| **Reaching the Buy Now price meets the reserve**                                                                                          | The seller pre-agreed to that price, so a Buy Now can never end as "reserve not met".                                                                                                                              |
| **Write-lock timeout → `503 busy` + `Retry-After`**                                                                                       | Nothing was written, so it is safe to retry; the client gets an actionable code instead of a generic 500.                                                                                                          |

## Slice 4 — Live updates

| Decision                                                                                           | Why                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Server-Sent Events** (`GET /api/events`) rather than WebSockets                                  | Updates only flow server → client (bids are ordinary POSTs). SSE is plain HTTP through the Vite proxy, and `EventSource` reconnects by itself. Uses FastAPI's native `EventSourceResponse`, which also sends keep-alive pings.                                           |
| **In-process broker, thread-safe publish** (`call_soon_threadsafe`)                                | Bids commit in threadpool workers and the simulator thread; subscribers live on the event loop. One process is enough here — with several workers this becomes Redis pub/sub or Postgres `LISTEN/NOTIFY`.                                                                |
| **Events personalized at delivery** (`outbid_you`, `is_you`, `is_high_bidder`)                     | The same bid is "you're winning" for one buyer, "you've been outbid" for the previous leader, and a price tick for everyone else — no client-side guesswork.                                                                                                             |
| **Publish only after commit; never for idempotent replays**                                        | Subscribers never hear about a bid that rolled back, or the same bid twice.                                                                                                                                                                                              |
| **Slow subscribers are cut off** (bounded queue → end the stream)                                  | A stalled tab can't grow memory without bound; it reconnects and refetches.                                                                                                                                                                                              |
| **Bidder id validated in a dependency, not inside the stream**                                     | Dependencies run before the `200` and stream headers are sent, so a bad id still gets a real `400` (a test caught the first version getting this wrong).                                                                                                                 |
| **Rival simulator: plausible, not rigged**                                                         | Rivals counter a human leader only after 20s, stop at a private per-vehicle ceiling (≈ reserve, or 1.3–1.6× start), concentrate on lots closing soon, and bid through the same `place_bid` service — every rule applies to them too. `SIMULATOR_ENABLED=0` turns it off. |
| **Publishing is best-effort** (errors logged, never raised)                                        | The bid is already committed; a broker hiccup must not turn a successful bid into a 500 that tempts the buyer to bid again.                                                                                                                                              |
| **`has_bid` in events is exact** (the bid transaction records everyone who has bid on the vehicle) | Clients replace their snapshot with the event's — no merge rules pushed onto the client.                                                                                                                                                                                 |
| **No SSE event ids; `hello` on every (re)connect means "resync"**                                  | Events aren't replayable, so ids would promise resumability that doesn't exist. Refetching on reconnect is simple and correct.                                                                                                                                           |
| **Simulator reads to choose, locks only to bid**                                                   | Scanning inventory under the write lock made human bids queue behind a robot.                                                                                                                                                                                            |
| **`python -m app.serve` entrypoint** (logging + 2s graceful-shutdown timeout)                      | Open SSE streams never end on their own; without the timeout, Ctrl-C and `--reload` hung. Verified: shutdown with an open stream takes 2s.                                                                                                                               |

## Slice 5 — Web foundation & design system

**Subject, audience, job.** Wholesale vehicle auctions for dealership buyers — at a desk during the day, on a phone on the lot. Their job: find a car worth bidding on, judge condition fast, and bid with confidence. The first instinct (a grid of rounded vehicle cards with a blue accent) is the generic SaaS default, so the design borrows from the auction world instead:

| Decision                                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Run list, not a card grid** (next slice)                                                                                                                                                                                   | Auctions publish run lists — dense rows a buyer scans. More information per screen and not the card template.                                                                                                                                                         |
| **Condition lights** (green / yellow / red), derived from title + damage severity, with the rule shown in a legend                                                                                                           | Borrowed from the lights over a physical auction lane. One glance answers "can I trust this car?". The one bold element of the design.                                                                                                                                |
| **Barlow + Barlow Condensed** (self-hosted, Latin subset only)                                                                                                                                                               | Barlow is modelled on North American highway signage — automotive vernacular rather than Inter-by-default (the design skill's suggested Playfair body text was rejected for a data-dense tool). The condensed cut with tabular figures carries prices and countdowns. |
| **Semantic tokens; signal colours have one meaning each** — green = you're winning, red = outbid / as-is, amber = time pressure, blue = actions                                                                              | Colour is information, never decoration. Cool lane-grey surfaces and asphalt ink, borders over shadows, radius scaled by hierarchy (controls 6px, panels 10px).                                                                                                       |
| **Light and dark themes**, resolved before first paint from the saved choice or the OS                                                                                                                                       | No theme flash; one dark token block.                                                                                                                                                                                                                                 |
| **Illustrations instead of placeholder photos** — each body style drawn in the car's actual paint colour; the dataset's 3–6 "photos" become views (driver side, passenger side, front, rear, wheel, cabin) via viewBox crops | Honest (labelled as illustrations), consistent, offline, and uses real data (`body_style`, `exterior_color`).                                                                                                                                                         |
| **Typed API from the server's Pydantic models** (`npm run gen:api`, checked in CI)                                                                                                                                           | One source of truth for the contract; CI fails if the committed types drift. openapi-typescript needs TypeScript 5's compiler API, which TS 7 (the native port) doesn't ship — so the generator uses JSON Schema → TS instead of downgrading the app's compiler.      |
| **Server-corrected clock, one shared ticker**                                                                                                                                                                                | Every `server_time` (and the live stream's hello) updates an offset; all countdowns re-render from one 1s interval via `useSyncExternalStore`.                                                                                                                        |
| **TanStack Query** for server state, **React Router** with URL state, **Motion** via `LazyMotion` + `m` and `reducedMotion="user"`                                                                                           | Server data belongs in a cache that live events can update; Motion ships only the DOM-animation features used and honours the OS reduce-motion setting.                                                                                                               |
| **Anonymous bidder id** in `localStorage`, falling back to per-tab when storage is blocked                                                                                                                                   | Accounts are out of scope; the id is enough for "you're winning" and My bids.                                                                                                                                                                                         |

## Slice 6 — Inventory run list

| Decision                                                                                                                                                                             | Why                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Every filter lives in the URL**; search updates with `replace` after a 300ms pause                                                                                                 | Links are shareable, back works, refresh keeps your place — and typing doesn't flood history.                                                                                                                                         |
| **Rows, not cards**: illustration · vehicle + specs + condition light · price · time · watch                                                                                         | A run list is scanned top to bottom; the eye compares price and time in fixed columns.                                                                                                                                                |
| **Whole row is one link** (stretched title link) with the watch button above it                                                                                                      | One focus stop and one accessible name per vehicle instead of a nest of links.                                                                                                                                                        |
| **Standing shown twice**: a coloured edge (scan) and a tag (read)                                                                                                                    | "You're winning" / "Outbid" must jump out while scrolling, without relying on colour alone.                                                                                                                                           |
| **Status derived on the client from the server-corrected clock**                                                                                                                     | A row flips from "Ends in 4s" to "Ended" exactly at zero, without a refetch.                                                                                                                                                          |
| **Facets in a stable order** (status fixed, the rest alphabetical) — never by count                                                                                                  | Ordering by count made a checkbox jump away right after it was clicked (caught in browser QA).                                                                                                                                        |
| **Desktop: sticky filter rail · mobile: bottom sheet** with "Show N vehicles"                                                                                                        | The sheet's button doubles as the result count, so the buyer knows before closing whether the filters went too far.                                                                                                                   |
| **Native controls** (checkboxes, selects, number inputs in fieldsets); ranges apply on blur/Enter                                                                                    | Accessible and phone-friendly for free; no request per keystroke.                                                                                                                                                                     |
| **Previous results stay visible (dimmed) while a filter loads**                                                                                                                      | No flash to skeletons on every click.                                                                                                                                                                                                 |
| **Empty state offers each active filter as a one-click removal**                                                                                                                     | An empty screen should tell you how to get results back.                                                                                                                                                                              |
| **Watch is optimistic**, rolled back on failure                                                                                                                                      | Instant feedback for a low-risk toggle.                                                                                                                                                                                               |
| **Search: words match at word starts; punctuated words are also indexed split** (`A-0043` → `a 0043`, `F-150` → `f 150`); **4+ character tokens with digits also match inside VINs** | Browser QA found "ford" matching "Oxford White" paint and "x5" matching random VINs; review then caught that word starts alone broke partial lot and F-150 searches. Dealers look cars up by the last digits of a VIN, so that stays. |
| **Standing uses the API's vocabulary and rule** (one client function, `leading/outbid/won/lost`)                                                                                     | Review found a second, disagreeing copy that could flash "You won" on a reserve-not-met lot at the moment the clock ran out.                                                                                                          |
| **`useEffectEvent` for the debounced search**                                                                                                                                        | Live bids re-render the page constantly; with the callback as a dependency the 300ms timer never got to fire.                                                                                                                         |
| **Watch revalidates in both directions** with a snapshot rollback and cancelled in-flight fetches                                                                                    | Watching changes the "Watching" filter too, and a late refetch must not undo the optimistic toggle.                                                                                                                                   |

## Slice 7 — Vehicle detail & bidding

| Decision                                                                                                                                               | Why                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Two-step confirm in place** ("Place bid $23,300" → "Confirm $23,300 bid") rather than a modal                                                        | A five-figure commitment deserves a deliberate second click, but a modal breaks flow when bidding is time-sensitive.                                                            |
| **One idempotency key per confirmed attempt**, kept across a network failure, dropped once the server answers                                          | A retry after a dropped connection can never place a second bid.                                                                                                                |
| **Quick amounts** (minimum, +1 and +2 increments) and a validated custom amount                                                                        | Most bids are the minimum; jump bids are one tap. Below-minimum, the 3× fat-finger cap and "that's at Buy Now" are explained as you type — the server re-checks under its lock. |
| **The draft follows the live minimum until you type**; a `bid_too_low` rejection snaps it to the new minimum and keeps the message                     | First draft remounted the form whenever the minimum moved — which would have erased "Someone bid first" the instant it appeared (caught in self-review before running).         |
| **Rejections update the page from the server's fresh snapshot**                                                                                        | "Someone bid first. The minimum bid is now $23,800." with the new amounts already in place — no reload.                                                                         |
| **Leading replaces the form with a calm sentence**                                                                                                     | Raising your own winning bid is blocked server-side; the UI doesn't offer it.                                                                                                   |
| **Price counts up with a spring; screen readers get the settled value**                                                                                | A change should read as a change. `useReducedMotion` jumps straight to the value.                                                                                               |
| **Condition report leads with trust**: branded-title banner, light + 1–5 grade meter, damage grouped Major → Mechanical → Cosmetic with buyer guidance | The buyer's real question is "what am I taking on?" — the worst news comes first.                                                                                               |
| **Bid panel sticky beside the content on desktop; on phones it follows the photos, with a sticky price/time/Bid bar**                                  | The panel is the reason you're on the page; on a phone the bar keeps it in reach while reading the condition report.                                                            |
| **Back returns to the run list as you left it** (history back when you came from the app, else a link to `/`)                                          | Filters and page survive the round trip; a shared link still has a way out.                                                                                                     |
| **Illustration frames use the drawing's 40:17 ratio**                                                                                                  | A 2:1 frame cropped the rear bumper off the side view (caught in browser QA).                                                                                                   |
